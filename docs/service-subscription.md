# Сервисная подписка

Бот запрашивает материал существующего доступа с `material_version=2`. Для готового
сервисного доступа SaaS возвращает только access ID, статус, готовность, версию
материала, тип `service_subscription`, актуальную ревизию и HTTPS URL подписки.
Бот сверяет URL и ревизию с отдельным чтением кабинета того же владельца.
Неизвестная версия, лишние поля и неверный адрес закрывают выдачу; адрес не
попадает в диагностические сообщения.

Одна ссылка содержит профили всех принятых Entry. Бот не выбирает первую ноду,
не создаёт для такого материала локальный ключ с одной панельной идентичностью
и не вызывает оплату или создание сервера при выдаче. Ссылка поступает в
существующий экран подключения. Кнопка «Продлить в кабинете» ведёт на проверенный
`/pricing?accessId=<свой доступ>` из SaaS; используется существующая покупка.

Старые ответы без полей новой версии проходят прежнюю проверку и сохраняют
локальную проекцию, продление и замену ключа. Старый клиент API без явного
запроса версии не получает материал многонодового доступа. SaaS включает новую
выдачу отдельным флагом, выключенным по умолчанию; обновление бота само его не
открывает. Откат бота требует сначала закрыть выдачу нового формата в SaaS.

Локальные проверки используют синтетические адреса и сообщения. Они не
подтверждают доставку в Telegram или работу VPN в клиенте.
